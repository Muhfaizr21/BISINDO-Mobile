1. Judul dan Identitas Proyek

Nama / Judul Aplikasi: BISINDO AI: Indonesian Sign Language Vision & Learning Ecosystem.

Identitas Pengembang: Proyek ini dikerjakan secara berkelompok oleh Muhammad Faiz Ramadhan (NIM: 2305072) dan Nailyaa Dliyaa’an Syah (NIM: 2305075), mahasiswa Program Studi Rekayasa Perangkat Lunak.

Deskripsi Singkat Aplikasi: BISINDO AI adalah ekosistem perangkat lunak terintegrasi yang berpusat pada aplikasi mobile Android (dibangun menggunakan Flutter) sebagai sistem utama penerjemah Bahasa Isyarat Indonesia (BISINDO) secara langsung (real-time) berbasis visi komputer on-device (Google MediaPipe 21-Landmark). Seluruh komputasi visi berjalan langsung pada perangkat mobile untuk menjamin privasi dan kecepatan. Ekosistem ini dilengkapi portal web responsif berbasis React JS dan Tailwind CSS yang berfungsi khusus sebagai landing page, media pengenalan produk, dokumentasi spesifikasi teknis, serta sarana pengunduhan aplikasi. Di sisi peladen, backend REST API berbasis Golang (MVC + SOLID) dan Supabase PostgreSQL menangani sinkronisasi data riwayat secara offline-first.

2. Latar Belakang dan Permasalahan

2.1. Permasalahan yang Ingin Diselesaikan

Berdasarkan data Badan Pusat Statistik dan organisasi disabilitas, terdapat lebih dari 2,5 juta penyandang disabilitas rungu dan tuli di Indonesia yang menghadapi hambatan komunikasi struktural dalam kehidupan sehari-hari. Permasalahan mendasar yang diidentifikasi meliputi:

  1. Kesenjangan Komunikasi Dua Arah: Mayoritas masyarakat dengar tidak memahami bahasa isyarat alami Indonesia (BISINDO), sehingga Teman Tuli mengalami kesulitan saat mengakses fasilitas kesehatan, pelayanan perizinan publik, pendidikan formal, dan kesempatan kerja profesional.
  2. Keterbatasan Juru Bahasa Isyarat (JBI): Jumlah tenaga penerjemah manusia bersertifikasi resmi sangat terbatas dan terkonsentrasi di kota-kota besar, sehingga mustahil hadir mendampingi setiap kebutuhan mendesak harian.
  3. Kelemahan Solusi Aplikasi Konvensional: Solusi perangkat lunak yang beredar saat ini umumnya hanya berupa kamus 2D statis tanpa interaktivitas kamera, atau mengandalkan pengiriman video mentah ke peladen awan (cloud video streaming). Skema pengiriman video ke server awan ini memicu latensi tinggi (> 500 ms), memerlukan kuota besar, dan sangat rentan melanggar privasi rekaman video personal pengguna.

2.2. Alasan dan Urgensi Pengembangan Aplikasi

Pengembangan BISINDO AI mendesak dilakukan karena menghadirkan terobosan On-Device Edge Computing: seluruh pemrosesan frame video kamera dilakukan secara lokal pada memori perangkat (RAM) tanpa mengirim data visual ke internet, menjamin perlindungan privasi mutlak bagi pengguna. Selain itu, latensi pengenalan sangat rendah (< 15 ms per frame pada 60 FPS), menghasilkan dialog yang mengalir alami. Sistem juga mematuhi standarisasi PUSBISINDO dengan mendukung pembentukan gestur satu tangan maupun dua tangan.

2.3. Target Pengguna Aplikasi

  1. Komunitas Tuli / Teman Tuli: Sebagai sarana asistif portabel untuk menyampaikan pesan dan kebutuhan secara mandiri kepada masyarakat dengar tanpa rasa canggung.
  2. Masyarakat Umum dan Tenaga Pelayanan Publik: Tenaga medis, frontliner kantor pemerintahan, keluarga, dan pengajar yang perlu berkomunikasi secara cepat dan akurat dengan Teman Tuli.
  3. Pelajar dan Penggiat Inklusi: Pengguna pemula yang ingin mempelajari abjad dan tata isyarat BISINDO melalui sistem latihan mandiri berbasis kamera.

4.1. Penerapan Clean Architecture pada Klien Mobile (Flutter)

Klien mobile menerapkan Clean Architecture rancangan Robert C. Martin yang membagi modul ke dalam tiga lingkaran independen dengan arah dependensi ke dalam:

  • Domain Layer (Pure Dart): Pusat aturan bisnis yang tidak memiliki dependensi terhadap framework Flutter maupun pustaka luar. Berisi entitas data (HandLandmark, GestureResult, HistoryItem), kontrak abstrak antarmuka (HistoryRepository, LearnRepository), dan kasus penggunaan (GetHistoryUseCase, SaveHistoryUseCase).
  • Data Layer: Bertanggung jawab atas pengelolaan data konkret. Mengimplementasikan kontrak repositori Domain melalui HiveLocalDataSource untuk akses offline dan HttpRemoteDataSource untuk komunikasi dengan backend Golang. Pada layer ini juga terdapat AIService yang menghubungkan JS-Interop MediaPipe.
  • Presentation Layer: Berisi antarmuka pengguna (UI) dan logika presentasi. State aplikasi dikelola secara reaktif oleh HistoryBloc, LearnBloc, dan NavigationCubit, memastikan tampilan terpisah sempurna dari logika bisnis.

4.2. Penerapan Pola MVC dan Prinsip SOLID pada Backend (Golang)

Backend REST API dibangun menggunakan bahasa Go dengan struktur MVC yang diperkuat prinsip SOLID: Controller murni bertugas memvalidasi request HTTP dan mengembalikan respons JSON; Service mengorkestrasi logika bisnis dan validasi data; sedangkan Repository menjadi abstraksi akses ke basis data Supabase (menerapkan Dependency Inversion Principle). Pendekatan ini memungkinkan penggantian sumber data tanpa memodifikasi lapisan controller.

5.2. Alur Komunikasi Antara Klien, Layanan AI, dan Backend

Komunikasi sistem menerapkan pola desentralisasi beban: Layanan AI berjalan sepenuhnya di sisi klien (in-browser / on-device) melalui jembatan JS-Interop / WebAssembly. Setelah MediaPipe mengekstrak 21 koordinat sendi tangan, Geometric Classifier internal langsung memutuskan karakter tanpa perlu menunggu respons jaringan. Saat gestur terkonfirmasi, data teks segera ditulis ke basis data lokal Hive. Pada saat bersamaan, klien mengeksekusi panggilan asynchronous HTTP POST ke Backend Golang untuk menyimpan rekaman ke Supabase, sehingga antarmuka tetap berjalan pada 60 FPS tanpa jeda I/O.

5.3. Rancangan Basis Data Relasional (Supabase PostgreSQL)

Skema basis data dirancang efisien dengan pengindeksan terbalik pada kolom waktu untuk memastikan query riwayat berlangsung instan:

-- 1. Tabel Riwayat Terjemahan (History) CREATE TABLE IF NOT EXISTS public.history ( id TEXT PRIMARY KEY, text TEXT NOT NULL, confidence DOUBLE PRECISION NOT NULL DEFAULT 0.95, timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW() ); CREATE INDEX IF NOT EXISTS idx_history_timestamp ON public.history (timestamp DESC); -- 2. Tabel Materi Pembelajaran (Learn Materials) CREATE TABLE IF NOT EXISTS public.learn_materials ( id TEXT PRIMARY KEY, title TEXT NOT NULL, description TEXT NOT NULL, category TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW() ); CREATE INDEX IF NOT EXISTS idx_learn_materials_category ON public.learn_materials (category); -- 3. Kebijakan Keamanan Akses Data (Row Level Security / RLS) ALTER TABLE public.history ENABLE ROW LEVEL SECURITY; ALTER TABLE public.learn_materials ENABLE ROW LEVEL SECURITY; CREATE POLICY "Allow public read access" ON public.history FOR SELECT USING (true); CREATE POLICY "Allow public insert access" ON public.history FOR INSERT WITH CHECK (true); CREATE POLICY "Allow public delete access" ON public.history FOR DELETE USING (true); CREATE POLICY "Allow public read learn" ON public.learn_materials FOR SELECT USING (true);

6.3. Target Hasil Akhir yang Ingin Dicapai

Keberhasilan proyek diukur melalui parameter kuantitatif dan kualitatif berikut:

  • Akurasi Pengenalan Handal: Akurasi klasifikasi abjad A-Z BISINDO mencapai > 90% pada pencahayaan wajar dengan latensi inferensi di bawah 15 milidetik per frame.

  • Ketahanan Offline Penuh: Pengguna dapat menerjemahkan dan menyimpan riwayat komunikasi meski jaringan internet terputus total tanpa mengalami kegagalan aplikasi (crash).
  • Kepatuhan Standar Rekayasa: Penerapan Clean Code, SOLID principles, serta pengujian otomatis berkelanjutan dengan kelulusan 100%.
